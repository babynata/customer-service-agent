# FAQ 向量数据库 — 设计方案

> 版本：v1.0 | 日期：2026-05-28 | 状态：先行文档

---

## 1. 背景与问题

当前客服 Agent 的 FAQ 检索采用**关键词匹配**：遍历预定义关键词列表，如果用户 query 包含关键词即返回对应答案。

### 1.1 关键词匹配的局限

| 问题类型 | 示例 | 关键词匹配结果 |
|---------|------|--------------|
| 同义词 | "退货" vs "退款" | 仅命中"退款"，"退货"查不到 |
| 语义相似但关键词不同 | "东西坏了怎么办" vs "商品损坏" | 查不到 |
| 口语化表达 | "能退不" vs "退款" | 查不到 |
| 多轮追问 | "那运费谁出"（上文已提退款） | 缺乏上下文，无法理解 |
| 规模瓶颈 | FAQ 条目 > 1000 | 遍历效率 O(n)，延迟不可接受 |

### 1.2 目标

构建一个**语义检索驱动的 FAQ 向量数据库**，支持：
- 语义相似度匹配（同义词、口语化、变体表达）
- 混合检索（向量 + 关键词，互补短板）
- 可扩展（万级 FAQ 延迟 < 100ms）
- 可解释（返回召回来源，运营可分析）
- 低运维（优先云托管，减少自建集群）

---

## 2. 核心设计决策

### 2.1 技术选型对比

| 维度 | 方案 A：云 API（P0） | 方案 B：自托管 Milvus（P1） |
|------|-------------------|--------------------------|
| 向量数据库 | 无（内存 numpy） | Milvus / Qdrant |
| 嵌入模型 | 火山方舟 Embedding API | 本地 BGE + 方舟备份 |
| 延迟 | ~200ms（含 API 往返） | ~20ms（本地） |
| 容量 | ≤ 1000 条（内存） | 百万级 |
| 运维 | 零运维 | 需维护 Milvus 集群 |
| 成本 | 按调用量计费 | 机器成本 + 人力 |
| 推荐阶段 | 验证期 / 小规模 | 规模化 / 成本敏感 |

### 2.2 决策结论

**两阶段演进**：
1. **P0（当前）**：方舟 Embedding API + numpy 内存检索 —— 零运维，快速验证效果
2. **P1（规模化）**：Milvus 自托管 + 本地 BGE —— 降延迟、降成本、扩容量

## 3. 数据模型

### 3.1 FAQ 文档 Schema

```python
class FAQDocument(BaseModel):
    id: str                    # 唯一标识，如 "faq_refund_001"
    question: str              # 标准问题
    synonyms: list[str]        # 同义词 / 口语化变体
    answer: str                # 标准答案（支持 Markdown）
    category: str              # 分类：退款/物流/发票/...
    tags: list[str]            # 标签：高优先级 / 活动期 / ...
    confidence_threshold: float = 0.75  # 该条目的匹配阈值
    created_at: str            # 创建时间
    updated_at: str            # 更新时间
    hit_count: int = 0         # 命中次数（运营分析）
    source: str = "manual"     # 来源：manual / mined / llm_generated
```

### 3.2 检索结果 Schema

```python
class FAQSearchResult(BaseModel):
    matched: bool
    answer: Optional[dict]     # {answer, confidence, category}
    sources: list[dict]        # Top-K 召回详情（可解释性）
    query_embedding: list[float]  # 调试用
    latency_ms: int            # 检索耗时
```

## 4. 检索流程

```
用户 query
  ↓
文本清洗（去停用词、标准化）
  ↓
Embedding（方舟 API / 本地 BGE）
  ↓
向量检索（numpy / Milvus ANN）
  ↓
混合打分：向量相似度 × 关键词 bonus
  ↓
Top-K 召回 → 阈值过滤
  ↓
重排序（可选 BGE Reranker）
  ↓
返回结果 + 来源追溯
```

### 4.1 混合打分公式

```
final_score = cosine_similarity(query_vec, doc_vec)

# 关键词 bonus
if 任意关键词命中 doc.question 或 doc.synonyms:
    final_score += 0.15

# 分类上下文 bonus（多轮对话中）
if 上一轮意图分类 == doc.category:
    final_score += 0.05
```

### 4.2 阈值策略

| 场景 | 阈值 | 说明 |
|------|------|------|
| 高置信度自动回复 | ≥ 0.85 | 直接返回，无需人工确认 |
| 标准回复 | 0.72 ~ 0.85 | 返回，但 thinking_log 标注"语义匹配" |
| 低置信度 | < 0.72 | 转人工或兜底回复 |

## 5. 运营闭环

### 5.1 数据回流

每次 FAQ 检索后，记录到数据仓库：
- query 原文
- 命中 / 未命中
- 最高相似度分数
- 返回的 answer_id
- 用户反馈（点赞 / 点踩）

### 5.2 冷启动与迭代

| 阶段 | 动作 | 产出 |
|------|------|------|
| 冷启动 | 导入历史客服对话 TOP-100 问题 | 初始 FAQ 库 |
| 第 1 周 | 运营每日审核未命中 query | 补充同义词、新增条目 |
| 第 2-4 周 | 分析低置信度命中（0.72~0.85） | 优化答案质量 |
| 每月 | 跑聚类算法发现新意图 | 自动提示运营补充 |

### 5.3 同义词管理

运营后台提供「同义词挖掘」功能：
- 输入标准问题，LLM 自动生成 10 个口语化变体
- 运营审核后一键入库
- 自动 Embedding 并更新向量库

## 6. 风险与缓解

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| Embedding API 超时/限流 | 检索降级为关键词匹配 | 本地缓存 + 异步预热 + 熔断器 |
| 向量库数据不一致 | 返回错误答案 | 版本控制 + 蓝绿更新 + 回滚机制 |
| 阈值设置过严/过松 | 过多转人工 or 错误回复 | A/B 测试对比不同阈值的效果 |
| 恶意 query 攻击 | 资源耗尽 | 限流 + query 长度限制 + 敏感词过滤 |

